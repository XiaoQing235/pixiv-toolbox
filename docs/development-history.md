# Pixiv Toolbox 开发过程溯源

本记录依据原始会话的工具调用、工具结果、首次 Git 暂存留下的文件对象和原始提交事后重建。阶段提交是在溯源时新建的，不是开发当时已经存在的提交；提交时间使用重建时的实际时间。原始 `main` 的 `9435d6b` 保持不变，重建结果位于 `reconstructed/development`。

## 证据与边界

- R01 是主会话，R05 是双端实现审阅，R07 是数据与任务实现，R08 是界面与浏览器验证，R09 是媒体实现与测试。`Rxx:行号` 指各自原始会话日志中的一行；本机来源索引单独保存，不纳入 Git。
- `development-events.json` 记录 67 个用于恢复状态的事件：60 次成功补丁、4 次文本替换、2 次依赖清单观察或变更，以及首次暂存时锁文件的内容。事件时间为 UTC，阶段表使用北京时间。
- 源码曾由多个子任务并行修改。阶段快照按有记录的操作时间和文件内容重放，阶段边界是溯源时选定的近似时间窗口，并非原来真实存在的提交边界。不能据此推断每个时间点磁盘上所有进程的瞬时状态。
- 包管理器生成的早期 `pnpm-lock.yaml` 未有完整内容快照；重建历史在首次暂存的可证实节点加入该文件，之前缺少该文件不表示它当时不存在。依赖清单在日志可见的版本及后续包管理器操作基础上还原。
- 忽略目录、下载的测试浏览器、浏览器配置、构建输出和本地调试数据不纳入阶段提交。失败的补丁与拒绝的权限声明不会当作已发生的修改重放。
- 首次暂存节点的 44 个文件与当时 Git 对象逐项一致，最终实现节点的树与 `9435d6b` 完全一致。首次暂存内容依据当时的差异输出及 Git 中保留的七个旧 blob 还原；其余文件沿用最终提交中的相同 blob。
- 每个重建快照经过 BetterLeaks `--redact --regex-engine stdlib` 扫描，退出码均为 0，并检查未包含本机用户路径。这个扫描属于本次溯源验证，不代表当时每个阶段都做过同样的检查。

## 查看历史

```sh
git log --reverse --stat reconstructed/development
git log --oneline --decorate --all
```

重建分支的每个阶段提交都标明 `Reconstructed: yes` 和对应的原始时间窗口；阶段结束后另有本溯源说明提交。要核对最终实现节点与原始提交，读取其提交说明中的 `Original-commit`，比较两个树；说明提交额外添加的文档不属于原始实现。
